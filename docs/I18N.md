# Internationalisation

ChainBeat ships **exactly 60 interface languages** — the list in the product brief, in its order — with a complete
catalog for each. Completeness is verified automatically (see [Tests](#tests)). **Linguistic quality is not**: read
the next section before relying on any translation.

## Read this first: the translations are machine-assisted and unreviewed

- **No native speaker has reviewed any of the 59 non-English catalogs.** `npm run i18n:check` proves that every key,
  plural form and `{{placeholder}}` is present; it cannot tell whether a sentence is natural, accurate or polite.
- **Professional human linguistic review is recommended before any public production launch**, for every language,
  and is essential for the lower-resource ones (Burmese, Khmer, Lao, Amharic, Hausa, Sinhala, Swahili, Nepali and the
  other Indic languages), where the model is weakest.
- How the catalogs were produced (details in [scripts/mt/README.md](../scripts/mt/README.md)):
  - **8 languages** (`th`, `ar`, `es`, `zh-CN`, `ja`, `ko`, `fr`, `de`): written directly by the AI assistant that built
    the project (the first ~640 strings), with the strings added later machine-translated and the 130 core terms kept
    consistent with the existing wording. Thai's later additions were again written directly.
  - **51 languages**: translated by NLLB-200 (distilled, 600M parameters) run locally, with `{{placeholders}}` and
    plural forms protected, a **hand-written 130-term glossary** per language overriding the model for the most visible
    UI words (navigation, buttons, table headers, statuses), and a crude round-trip check that flagged 15–55 % of
    strings per language as low-agreement. Flagged strings were **not** individually reviewed.
- The **`auth` namespace** (sign-in pages, ~170 strings, added after the rest) was produced as follows: Thai written
  directly by the AI assistant; the other 58 languages machine-translated with the same NLLB pipeline (new keys only,
  `run.py --only`), after which the labels *Sign in, Sign out, Create account, Username, Password, Email address* and the
  two Google button captions were **overwritten with hand-written wording for every language** (the model had rendered
  "Sign in" as "Subscribe" in Russian and "Register" in Spanish). Those overrides are the assistant's, not a native
  speaker's. Spot checks of the raw output also showed stiff or garbled sentences (e.g. "attempt left"), which is why
  that message was reworded to a form the model handles ("Attempts remaining: N").
- **Ten governance strings** (the "Other" category, *Voting starts*, the proposal history heading and *Result*, *Copy
  proposal number*, *Voting period* on the create form, and the save / restore / discard draft texts) were added with the
  full-screen Proposals work. Thai was written directly; the other 58 were machine-translated as above, and the
  assistant then **hand-wrote all ten for 21 languages** (`ar`, `es`, `zh-CN`, `zh-TW`, `ja`, `ko`, `fr`, `de`, `pt-BR`,
  `it`, `nl`, `ru`, `uk`, `pl`, `tr`, `vi`, `id`, `hi`, `sv`, `cs`, `he`) because the model had turned the button labels
  into nonsense (Spanish "Discard draft" became "Descarga el borrador" — "download the draft"; Japanese "Save draft"
  became "save remarks"; "Copy proposal number" became "copy number of the proposal" in several languages). The other 37
  languages keep the raw model output for those ten strings, **including the button labels, which are the likeliest to
  be wrong**. None of it was reviewed by a native speaker.
- Expect: odd word choices for short labels that are not in the glossary, terminology that differs between a label
  and the sentences around it, and stiff sentences. Do **not** treat "60 languages" as "60 production-quality
  localisations".
- The NLLB model weights are licensed **CC-BY-NC 4.0 (non-commercial)**; check that before using generated text
  commercially.
- Demo content — proposal titles and bodies, repository and validator names — is English only (it stands in for
  on-chain data, which is not translated either).

## How it works

- `i18next` + `react-i18next` + `i18next-browser-languagedetector`. Detection order: saved choice
  (`localStorage['chainbeat.lang']`) → browser language → English.
- **18 modular namespaces** (`common`, `navigation`, `dashboard`, `metrics`, `explorer`, `transactions`, `blocks`,
  `wallet`, `staking`, `validators`, `governance`, `analytics`, `visualizations`, `settings`, `notifications`, `errors`,
  `accessibility`, `auth`) — one JSON file per namespace per language under `src/i18n/locales/<code>/`.
  `src/i18n/namespaces.json` maps each top-level key group to its namespace.
- **Lazy loading.** English is bundled; every other language is loaded on demand, namespace by namespace, and the UI
  switches only after the catalog is in, so a raw key is never flashed. A missing key falls back to English.
- **Formatting** never uses string concatenation: `src/lib/format.ts` wraps `Intl.NumberFormat`, `DateTimeFormat`,
  `RelativeTimeFormat` and `PluralRules` with the language's locale. Digits stay Latin for scripts whose default digits
  would make addresses, hashes and amounts hard to read (`-u-nu-latn` for Arabic, Persian, Urdu, Bengali, Marathi,
  Nepali, Burmese, Khmer, Lao); compact numbers use Latin K/M/B for Arabic and cap CJK figures at four significant digits.
- **Plurals** use each language's CLDR categories (`key_zero|one|two|few|many|other`); the build script generates exactly
  the categories `Intl.PluralRules` reports, so Arabic's six forms, Russian's four and Slovenian's dual all work.
- **Direction.** `<html lang dir>` follows the language; **Arabic, Hebrew, Persian and Urdu are right-to-left**. Layout
  uses logical properties (`ms-`, `pe-`, `start`, `end`), direction-implying icons mirror, and hashes, addresses and chart
  canvases are isolated as left-to-right runs (`.ltr-isolate`, `dir="ltr"`), so they stay readable inside RTL text.
- **Typography per script** (`html[data-script]` in `src/index.css`, fonts in `src/i18n/fonts.ts`): Inter/Manrope for
  Latin, Cyrillic, Greek and Vietnamese (bundled, no CDN); Noto Sans families for Thai, Arabic (also Persian, Urdu),
  Hebrew, Devanagari (also Marathi, Nepali), Bengali, Gurmukhi, Gujarati, Tamil, Telugu, Kannada, Malayalam, Sinhala,
  Myanmar, Khmer, Lao and Ethiopic, each loaded only when its language is selected. CJK uses the operating system's
  fonts (web fonts for them are multi-megabyte).
- **Text expansion.** Primary actions and metric labels wrap instead of truncating; metric figures shrink-to-fit
  (`useFitText`); KPI labels and hints wrap to two lines; header action groups wrap on narrow screens. The e2e suite
  checks every language for horizontal overflow and cut-off metric cards.

## Tooling

| Command | Purpose |
| --- | --- |
| `npm run i18n:check` | Exact 60-locale registry; every key used in code exists in English; every locale has exactly English's keys, the plural forms its language needs, the same `{{placeholders}}`, no empty strings, no `TODO`/`TBD` markers, and is not mostly English. Flags: `--verbose`, `--unused` (English keys no code references), `--only=th,ar`, `--allow-partial` (progress runs only) |
| `node scripts/export-locale.mjs [code] [--missing-from en]` | Print a catalog as a flat `key=value` list |
| `node scripts/build-locale.mjs <code> <list.txt> [--merge]` | Build a locale from a flat list; refuses anything incomplete or unknown |
| `node scripts/i18n-add.mjs <list.txt> [--overwrite]` | Add or change English strings (routed to the right namespace file) |
| `node scripts/i18n-remove.mjs <key…>` | Remove keys from English and every locale |
| `python scripts/mt/run.py …` | The optional machine-translation pipeline ([README](../scripts/mt/README.md)) |

### Adding or changing a string

1. Add it to English: put `group.key=English text` in a list and run `node scripts/i18n-add.mjs list.txt`.
2. Translate the new strings for every locale: `node scripts/export-locale.mjs th --missing-from en` lists what a
   locale lacks; translate it (or use the pipeline in `scripts/mt` with `--only`), then
   `node scripts/build-locale.mjs th th-new.txt --merge`.
3. `npm run i18n:check` must pass for all 60 locales; `npm test` and `npm run test:e2e` cover the rest.

### Adding a language

Add a row to `src/i18n/languages.json` (and to the required list in `scripts/i18n-check.mjs` and
`src/i18n/i18n.test.ts`), export English, translate, `build-locale.mjs`, then run the checks. A language whose script is
not in `ScriptId` also needs a `html[data-script=…]` stack in `src/index.css` and, if a web font is needed, an entry in
`src/i18n/fonts.ts`.

## Tests

- **Unit (`src/i18n/i18n.test.ts`)**: the registry is exactly the 60 required locales in order; every locale has a
  catalog; each has exactly English's keys, every plural form its language needs and the same placeholders; no empty or
  `TODO` strings and no English copied across; every locale loads on demand and resolves a label; switching updates the
  text, `<html lang dir data-script>` and persists; Arabic, Hebrew, Persian and Urdu are RTL and English returns to LTR;
  language-tag resolution; Latin digits for the scripts that need them; plural selection (Arabic dual/few, English
  one/other).
- **End-to-end (`tests/e2e`)**: every locale at 320 px and 1280 px over six routes (translated shell, correct direction,
  no horizontal overflow, no console errors); every locale at 11 viewport sizes with no cut-off metric card; the picker
  lists 60 languages and finds one by English name; Thai (font loaded on demand, persists across reload) and Arabic in
  depth; Hebrew, Persian and Urdu are RTL with hashes still left-to-right.

## Known gaps

- Nobody has reviewed any screen in any language beyond automated checks and a few spot checks (Thai, Russian and a
  handful of others, by reading); layout was checked automatically (overflow, truncation), not by visual review of
  every screen everywhere.
- Short labels outside the glossary, and everything in the lowest-resource languages, are the likeliest to be wrong.
- No language has been tested with a screen reader.
- Where a language has script variants only one ships: Serbian is Cyrillic (no Latin variant), Norwegian is Bokmål.
